総合順位の式

モデルの総合は、「能力」と「速度点」を組み合わせて出します。能力は問ごとの点の平均です。速度点は、答えを出すまでの時間の短さです。式は次のとおりです。

  • 能力 = 回（問）ごとの点数（0〜1）の平均。答えなし・上限・時間切れ・時間の上限で飛ばした問は 0 点
  • 速度点 = (ln T_max − ln T) ÷ (ln T_max − ln T_min)。T は時間の中央値。最も遅いモデルが 0、最も速いモデルが 1
  • 総合 = 0.7 × 能力 + 0.3 × 速度点

2. 3D 数学（1 問）

3D 数学

3 本の線分に沿って動かした球が作る立体

空間の 3 本の線分に沿って球を動かしてできる立体について、切り口の範囲、重なりの条件、体積を答える問題です。

やること

3 本の線分に沿って球を動かしてできる 3 つの立体 V1・V2・V3 について、4 つの小問に答えます。(1) は切り口を調べる範囲、(2) は立体どうしの重なりの条件、(3) は 1 つの立体の体積、(4) は 3 つを合わせた立体の体積です。答えは、球の半径 r を使った式で書きます。

問題の状況

空間に 4 つの点 O・A・B・C があります。座標は O=(0,0,0)、A=(1,0,0)、B=(1,1,0)、C=(1,1,1) です。

O から A、A から B、B から C へ線分を結ぶと、長さ 1 の線分が 3 本、階段のように直角に折れ曲がってつながります。OA は x の向き、AB は y の向き、BC は z の向きにのびています。

点 P が線分の上を端から端まで動くとき、P を中心とする半径 r の球（中までつまった球）が通った場所をすべて集めると、1 つの立体になります。OA の上を動かしてできた立体を V1、AB の上なら V2、BC の上なら V3 と呼びます。それぞれ、線分のまわりを太らせた、両端が丸い棒のような形です。

球の半径 r は、1/2 より大きく 1 より小さい数です。

小問と正解

小問何を答えるか正解
(1)y 座標が t の平面で立体を切ったとき、V1 と V3 の両方に切り口ができる t の範囲を求めます。さらに、そのときの V1 の切り口と V3 の切り口を、1 枚の図に描きます。1−r ≤ t ≤ r。断面は (x,z) 平面で、V1 は線分 (0,0)–(1,0) を半径 √(r²−t²) で太らせたスタジアム形、V3 は線分 (1,0)–(1,1) を半径 √(r²−(1−t)²) で太らせたスタジアム形
(2)V1 と V3 の重なり（両方に入る部分）が、V2 の中に完全に入るための r の条件を求めます。1/2 < r ≤ √2/2（= 1/√2）
(3)V1 の体積を求めます。πr² + (4/3)πr³
(4)(2) の条件を満たすとき、V1・V2・V3 のどれかに入る部分全体（3 つを合わせた立体）の体積を求めます。3πr² + (2π − 8/3)r³（r=0.6 で 4.1741、モンテカルロ 4.1747±0.0021）

具体例

条件
r=0.6
→
答え
4.1741

(4) の正解の式に r=0.6 を入れた値です。コンピュータに乱数で点をたくさん打たせて体積を数える検算（モンテカルロ）でも、4.1747±0.0021 になりました。

何が難しいか

  • 図が与えられません。3 つの立体の位置関係を、自分で組み立てる必要があります。
  • (2) は、V1 と V3 の重なりが空ではないことを見抜き、不等号の向きと端の扱い（≤ か <）まで正確に出す必要があります。記録には、不等号の向きを逆にした答えと、重なりを空と誤った答えがありました（どちらも gemma4:e4b）。
  • (4) は、V1 と V2 の重なりの体積 (π+4/3)r³ を正確に求める必要があります。
  • (4) は、足し引きをした式を最後に整理するところでも誤りやすい問題です。記録には、途中まで正しかった式を最後の書き換えで誤った答えがありました（qwen3.8:27b）。

何の力を見るか

図の無い空間図形を、式で表して最後まで正しく計算する力を見ます。考える力（頭の良さ）を測る問題です。

採点の仕方

小問 (1)〜(4) を 1 つずつ、○（正解）・×（誤り）・—（答えなし）で採点します。1 回の点は、正解した小問の割合です。(1) は t の範囲で採点し、切り口の図は、記述が明らかに誤っているときだけ注記します。正解はモンテカルロで検算してあります。ローカルのモデルの結果は、以前に解かせた記録（Documents/3D問題_実施モデル一覧_2026-10-08.md）を使いました。

3. コーディング（6 問）

コーディング

C1 シェル風の単語分割

コマンドのような文字列を、引用符やバックスラッシュの決まりに従って、単語のリストに分ける関数を書く問題です。

やること

関数 split_words を書きます。引数の文字列を、シェル（コマンドを文字で打ち込む画面）の引用の決まりを真似た規則で、単語のリストに分けます。引用符で囲んだ部分は、空白があっても単語の一部になります。# から行末まではコメントとして無視します。閉じていない引用符や、末尾の単独のバックスラッシュには、ValueError を出します。

具体例

入力
split_words("a 'b c'  d")
→
期待する答え
["a", "b c", "d"]

単一引用符の中の空白は、区切りになりません。

入力
split_words('x "y\\"z" # comment\n  w')
→
期待する答え
["x", 'y"z', "w"]

入力は Python の文字列リテラルで書いてあります。二重引用符の中の \" は " 1 文字になり、# から行末まではコメントとして無視されます。

入力
split_words("it's")
→
期待する答え
ValueError

閉じていない引用符なので、エラー（ValueError）になります。

何が難しいか

  • 引用符の種類で決まりが違います。単一引用符の中は、何も特別扱いしません。二重引用符の中で効くバックスラッシュは、直後が " \ $ ` のときと、直後が改行のとき（行の継続）だけです。それ以外は、ただの文字として残ります。
  • # がコメントになるのは、「単語の先頭」にあるときだけです。a#b の # や、空の引用のあとの # (''#x) は、ただの文字です。
  • 引用の外と二重引用符の中では、バックスラッシュのすぐ後ろが改行だと、その 2 文字は取り除かれます（行の継続）。取り除いたあとも、単語は切れません。
  • 区切りになるのは、半角スペース・タブ・改行の 3 種類だけです。\r や全角スペースは単語の一部です。'' や "" だけの単語は、空文字列の単語になります。

何の力を見るか

細かい規則を、例外まで含めて読み落とさずに実装する力（仕様の正確な読み取りと場合分け）を見ます。

  • 引用の外のバックスラッシュ（1 ケース）
  • 引用と引用の外のつなぎ、空の引用（空の単語）（2 ケース）
  • コメント（# が効く場所と効かない場所）（6 ケース）
  • 行の継続（引用の外・中・コメントとの組み合わせ）（3 ケース）
  • 区切りではない空白（\r・全角スペースなど）（1 ケース）
  • エラー（閉じていない引用符・末尾のバックスラッシュ）（3 ケース）

### 式の形

- 式は 5 つのフィールドを 1 個以上の半角スペースかタブで区切ったもの。先頭と末尾の空白は許す。順に「分」「時」「日」「月」「曜日」。

## 問題 C4: 厳密な JSON パーサ

関数 `parse_json(text: str) -> object` を書いてください。RFC 8259 の文法に厳密に従って `text` を 1 つの JSON の値として読み、Python の値に変換します。標準ライブラリの `json` モジュール（`json.loads`、`json.JSONDecoder` など）は使わないでください（使った答えは 0 点）。

### 文法

- `text` 全体が「空白（0 個以上）、値 1 つ、空白（0 個以上）」でなければならない。それ以外（空の文字列、空白だけ、値の前後の余計な文字、値が 2 つ）は `ValueError`。
- 空白は半角スペース、`\t`、`\n`、`\r` の 4 種類だけ。`\f`、`\v`、ノーブレークスペース、先頭の BOM（U+FEFF）は空白ではなく、`ValueError`。
- 値は、オブジェクト、配列、文字列、数、`true`、`false`、`null` のいずれか。トップレベルの値がオブジェクトや配列でなくてもよい（`"abc"` や `42` だけでも正しい）。
- リテラルは `true`、`false`、`null` の小文字だけ。`True`、`NULL`、`nul` は `ValueError`。`NaN`、`Infinity`、`-Infinity` も `ValueError`。
- オブジェクト `{ ... }` は Python の `dict`。キーは必ず文字列。`,` で区切り、末尾の余計な `,`（`{"a":1,}`）や空のメンバー（`{,}`）は `ValueError`。**同じキーが 2 回出てきたら `ValueError`**（エスケープを解いたあとの文字列として同じなら同じキー。`{"a":1,"\u0061":2}` は `ValueError`）。
- 配列 `[ ... ]` は Python の `list`。末尾の余計な `,` や空の要素（`[1,,2]`、`[,1]`）は `ValueError`。
- 文字列は `"` で囲む（`'` は不可）。中で使えるエスケープは `\"` `\\` `\/` `\b` `\f` `\n` `\r` `\t` と `\uXXXX`（16 進 4 桁。大文字小文字どちらも可）だけ。それ以外のエスケープ（`\a`、`\x41`、`\'`、`\U0001F600`、桁の足りない `\u12`）は `ValueError`。
  - 文字列の中にエスケープされていない制御文字（U+0000〜U+001F）があれば `ValueError`。U+007F 以降の文字（日本語や絵文字）はそのまま書いてよい。
  - `\uD83D\uDE00` のように上位サロゲート（U+D800〜U+DBFF）の直後に下位サロゲート（U+DC00〜U+DFFF）の `\u` エスケープが続くときは、合わせて 1 文字（この例では U+1F600）にする。下位サロゲートだけ、上位サロゲートの直後に下位サロゲートのエスケープが続かない、という場合は `ValueError`。`\u0000` は許される（長さ 1 の文字列 `"\x00"`）。
- 数は `-?(0|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?` の形だけ。先頭の `0` に数字が続くもの（`01`）、`+1`、`.5`、`1.`、`1e`、`0x10`、`1_000` は `ValueError`。小数部か指数部があれば Python の `float(その文字列)` と同じ値（`1e400` は `inf`）、どちらも無ければ `int`（桁数に上限はなく、正確な値。`-0` は `int` の `0`）。
- 入れ子の深さは最大 50,000（`[[[[...]]]]` のような深い入れ子でも、正しく値を返すこと）。`text` の長さは最大 1,000,000 文字で、その長さでも十分速く動くこと（たとえば、読み進めるたびに文字列を切り出す（`text = text[1:]`）作りでは間に合わない）。

例:
- `parse_json(' {"a": [1, 2.5, "x\\ny"], "b": {"c": null, "d": true}} ')` → `{"a": [1, 2.5, "x\ny"], "b": {"c": None, "d": True}}`
- `parse_json('"\\u3042\\uD83D\\uDE00"')` → `"あ😀"`
- `parse_json('[1, 2,]')` → `ValueError` を送出

## 問題 C5: 正規表現の部分集合のマッチャ

関数 `regex_search(pattern: str, text: str) -> bool` を書いてください。`pattern` が `text` のどこかの部分文字列（空の部分文字列も含む）に一致すれば `True`、しなければ `False` を返します。標準ライブラリの `re` モジュール（および `sre_parse`、`sre_compile`、`_sre`）は使わないでください（使った答えは 0 点）。

### パターンの文法

- 文字: 普通の文字はその文字そのものに一致する。大文字と小文字は区別する。
- `.`: 改行を含む任意の 1 文字に一致する。
- `\` の直後の 1 文字: その文字そのものに一致する（`\.` は `.`、`\\` は `\`、`\n` は改行ではなく `n`、`\d` は `d`）。パターンの末尾に単独の `\` があれば `ValueError`。
- 文字クラス `[...]`: `[` の直後の `^` は否定（`[^...]` は列挙した文字以外の 1 文字）。中身は左から順に項目として読む。項目を読むときは、まず 1 文字（`\` でエスケープされた文字も 1 文字と数え、エスケープを解いた文字になる）を読み、その直後が `-` で、さらにその次の文字が `]` でなければ範囲 `x-y`（`x` 以上 `y` 以下のコードポイント。`y` もエスケープできる。`x > y` なら `ValueError`）、そうでなければ読んだ 1 文字だけの項目とする。`]` はエスケープしない限り常にクラスを閉じる。`-` は項目の 1 文字目として読まれたとき、または `]` の直前にあるときはただの文字。クラスの中では `.` `*` `+` `?` `|` `(` `)` `^`（先頭以外）`$` はただの文字。項目が 1 つも無い `[]`、`[^]`、閉じていない `[` は `ValueError`。
- `^`: `text` の先頭（位置 0）にだけ一致する幅 0 のアサーション。`$`: `text` の末尾にだけ一致する幅 0 のアサーション（末尾の改行の前には一致しない）。パターンのどこに置いてもよい。
- 量指定子 `*`（0 回以上）、`+`（1 回以上）、`?`（0 回か 1 回）: 直前の要素（1 文字、`.`、エスケープした文字、文字クラス、グループ `(...)`）に付ける。付ける要素が無いとき（パターンの先頭、`(` や `|` の直後）、量指定子を重ねたとき（`a**`、`a*?`）、`^` や `$` に付けたときは `ValueError`。
- グループ `( ... )`: 中身を 1 つの要素にまとめる（キャプチャは要らない）。空のグループ `()` は空文字列に一致する。対応の取れていない `(` や `)` は `ValueError`。
- 選択 `|`: 優先順位は最も低く、左右のどちらかに一致すればよい。空の選択肢（`a|`、`|a`、`(|a)`）は空文字列に一致する。
- 空のパターン `""` はどの `text` にも一致する（`True`）。

### 性能

- `pattern` は最大 100 文字、`text` は最大 10,000 文字。
- バックトラックで指数時間になる作りは不可。`(a|aa)*b` や `(a*)*b` を `"aaaa…a"`（一致しない）と照合する場合や、`a*b` を 5,000 文字の `"aaaa…a"` と照合する場合でも、すぐに答えること（状態集合をたどる方式などを使う）。

例:
- `regex_search("^[a-z]+@[a-z]+\\.[a-z]+$", "foo@bar.com")` → `True`
- `regex_search("(cat|dog)s?$", "I like dogs")` → `True`
- `regex_search("a$", "a\n")` → `False`

JSON の取り出し

json3 社内の問い合わせから情報を取り出す

社内の問い合わせの文章から、部署・問い合わせた人の姓・システム名・エラーコード・影響を受けている人数・緊急度を取り出し、JSON で答える問題です。

やること

短い問い合わせを読み、6 つの鍵を持つ JSON オブジェクトを 1 つだけ出力します。人数は整数で、問い合わせた本人も含めます。緊急度は「高」「中」「低」から選びます。JSON のほかには何も書きません。

具体例

文章の一部

→
期待する値
"affected_users": 5

ほかの 4 人に、問い合わせた本人を足した 5 人です。

文章の一部
月末の締めが明後日なので、至急対応をお願いします。
→
期待する値
"priority": "高"

緊急度は、文面から 3 つの選択肢のどれかを判断します。

何が難しいか

  • 影響を受けている人数は、「ほかの 4 人」に問い合わせた本人を足した 5 です。文中の 4 をそのまま答えると誤りです。
  • 緊急度は、「至急対応をお願いします」などの文面から、3 つの選択肢のどれかを自分で判断します。
  • エラーコードは、画面に出た E-503 の文字列だけを書きます。
  • 問い合わせた人は姓だけ（田中）、部署は「経理部」と「部」まで含めて書きます。

何の力を見るか

文章の中から必要な情報だけを選び、決められた形式（鍵の名前・型・書式）で出力する力を見ます。

採点の仕方

6 項目それぞれを正解と比べ、一致した項目の割合が点です（1 項目 = 約 17%）。答えの JSON は、本文全体、コードブロックの中、最初の { から最後の } まで、の順に読み取ります。文字列は、全角と半角などの違いをそろえ、前後の空白を除いて比べます。整数と真偽値は型も見ます。JSON として読めないときは 0 点です。
