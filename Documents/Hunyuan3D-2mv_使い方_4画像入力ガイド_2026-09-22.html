Hunyuan3D-2mv の使い方

4方向画像の添付方法、ローカル実行、Python利用、生成設定、テクスチャ、出力形式、VRAM、現行実装上の注意点をまとめたレポートです。

一次情報を優先し、公式 README / Hugging Face Model Card / 公式 Gradio 実装 / 公式 examples を照合しています。公式資料同士で数値が食い違う箇所は、そのまま明記しています。

結論

4枚は「1枚に結合」せず、Front / Back / Left / Right の4枠へ個別に入れます。

公式 Gradio UI は 1〜4ビュー対応です。内部では4枚を front / back / left / right のキーで別々にパイプラインへ渡します。

Front（正面）は実質必須として扱うのが安全です。

現行 Gradio コードは「4枠のうち最低1枚」と判定する一方、生成後に image['front'] を参照する箇所があります。 そのため、背面だけ・側面だけで実行するより、常に正面画像を入れる運用を推奨します。

1. Hunyuan3D-2mv とは

Hunyuan3D-2mv は Tencent の Hunyuan3D-2 をマルチビュー制御（multi-view controlled shape generation）向けに調整したモデルです。

複数方向画像
→
Hunyuan3D-2mv
→
形状（Mesh）
→
Hunyuan3D-Paint
→
Texture付き3D

形状生成（Shape Generation）とテクスチャ生成（Texture Synthesis）は別段階です。Hunyuan3D-2mv は主に複数画像から形状を作る部分を担当します。

2. 4つの画像の添付方法

Gradio GUI

Hunyuan3D-2mv で起動すると MultiView Prompt に以下の4枠が表示されます。

Front正面画像
Back背面画像
Left左側面画像
Right右側面画像
  1. Front に正面をドラッグ＆ドロップ、またはクリックして選択。
  2. Back に背面。
  3. Left に左側面。
  4. Right に右側面。
  5. 形だけなら Gen Shape。
  6. テクスチャ環境まで導入済みなら Gen Textured Shape。
4枚をコラージュ画像にして1枠へ入れる方式ではありません。

公式実装では4枚を別オブジェクトとして受け取り、辞書 {"front": ..., "back": ..., "left": ..., "right": ...} へ格納します。

1〜3枚でも動くか

現行 Gradio のタイトルは「Image to 3D Generation with 1-4 Views」で、コード上も4枠すべてが空の場合だけエラーになります。ただし前述の image['front'] 参照があるため、Frontなし運用は避けるのが安全です。

3. 入力画像の作り方

項目推奨根拠の区分
対象4枚すべて同一オブジェクト・同一デザインマルチビュー整合性の実務上の推奨
画角カメラ高さ・距離・焦点距離を可能な限り統一実務上の推奨
大きさ画像内で対象の占有率を揃える実務上の推奨
背景透明背景、または単純な背景Gradioに Remove Background 機能あり
影強い落ち影、床反射、背景物を避ける実務上の推奨
左右Left / Right を取り違えない。左右非対称の目印があると検証しやすい公式はラベルを定義するが「被写体基準/観察者基準」の文章定義は未確認
解像度4枚とも同程度の解像度・アスペクト比にする実務上の推奨
「必ず 512×512」などの固定入力解像度は、今回確認した公式 README / Model Card では要件として明記されていません。

したがって固定値を仕様として断定しません。大きすぎる画像を入れても内部処理で前処理されるため、まず4枚の整合性を優先してください。

4. ローカル導入

公式 README は macOS / Windows / Linux 対応を掲げています。実際の CUDA GPU 利用では PyTorch、NVIDIA ドライバ、コンパイル環境の組み合わせが重要です。

基本導入

# 1) 公式リポジトリを取得
git clone https://github.com/Tencent-Hunyuan/Hunyuan3D-2.git
cd Hunyuan3D-2

# 2) 仮想環境（Linux例）
python3 -m venv .venv
source .venv/bin/activate

# Windows PowerShellなら例:
# py -m venv .venv
# .\.venv\Scripts\Activate.ps1

# 3) PyTorch は公式 PyTorch の案内に従って、
#    自分のOS / CUDA環境に適合するものを先にインストール

# 4) Hunyuan3D側
pip install -r requirements.txt
pip install -e .

テクスチャ生成も使う場合

cd hy3dgen/texgen/custom_rasterizer
python setup.py install
cd ../../..

cd hy3dgen/texgen/differentiable_renderer
python setup.py install
cd ../../..
Windowsでは上記カスタム拡張のビルドでコンパイラ環境が必要になる場合があります。

公式 README は Windows 対応を明記していますが、今回確認した本文では特定の Visual Studio Build Tools / CUDA Toolkit バージョンの組み合わせまでは固定していません。エラー時は実際のログを基準に切り分けるべきです。

5. Gradio GUI で使う

標準 Hunyuan3D-2mv

python3 gradio_app.py \
  --model_path tencent/Hunyuan3D-2mv \
  --subfolder hunyuan3d-dit-v2-mv \
  --texgen_model_path tencent/Hunyuan3D-2 \
  --low_vram_mode

Turbo版

python3 gradio_app.py \
  --model_path tencent/Hunyuan3D-2mv \
  --subfolder hunyuan3d-dit-v2-mv-turbo \
  --texgen_model_path tencent/Hunyuan3D-2 \
  --low_vram_mode \
  --enable_flashvdm

Windows では環境によって python3 ではなく python または py を使います。

遠隔GPUマシンで動かす場合

Gradio 実装の既定ホストは 0.0.0.0、ポートは 8080 です。LANへ公開されるので、必要なら --host 127.0.0.1 に限定するか、ファイアウォールで接続元を制限してください。

6. 主要設定

項目現行 Gradio の値意味
Generation ModeTurbo / Fast / StandardTurbo用UI。変更時の Steps は 5 / 10 / 30。
Inference StepsTurboモデル: 初期5、通常: 初期30拡散推論ステップ数。一般に増やすほど時間が増える。
Decoding ModeLow / Standard / HighOctree Resolution を 196 / 256 / 384 に切替。
Octree Resolution16〜512、初期256メッシュ復号の空間解像度。
Guidance Scale初期 5.0条件画像への追従強度に関係。
Number of Chunks初期 8000復号処理の分割関連パラメータ。
Remove Background初期 ON背景除去。
Randomize seed初期 ON毎回Seedを変える。
Seed初期 1234同条件の再現性を取りたい時はRandomizeをOFF。
Model Card のサンプル値と、現行 Gradio UI の初期値は一致していません。

Hugging Face の Hunyuan3D-2mv 例では num_inference_steps=30、 octree_resolution=380、num_chunks=20000。 一方、現行 Gradio は標準初期値として Octree 256、Chunks 8000 等を持っています。 「380 / 20000 が必須仕様」という意味ではありません。

7. Python から4枚を渡す

4枚を辞書として渡します。右側面も "right" キーで指定できます。

import torch
from PIL import Image
from hy3dgen.rembg import BackgroundRemover
from hy3dgen.shapegen import Hunyuan3DDiTFlowMatchingPipeline

paths = {
    "front": "front.png",
    "back":  "back.png",
    "left":  "left.png",
    "right": "right.png",
}

background_remover = BackgroundRemover()
images = {}

for view_name, image_path in paths.items():
    image = Image.open(image_path)

    # 背景が通常のRGB画像なら背景除去
    if image.mode == "RGB":
        image = background_remover(image)
    else:
        image = image.convert("RGBA")

    images[view_name] = image

pipeline = Hunyuan3DDiTFlowMatchingPipeline.from_pretrained(
    "tencent/Hunyuan3D-2mv",
    subfolder="hunyuan3d-dit-v2-mv",
    use_safetensors=True,
    device="cuda",
)

mesh = pipeline(
    image=images,
    num_inference_steps=30,
    octree_resolution=380,
    num_chunks=20000,
    generator=torch.manual_seed(12345),
    output_type="trimesh",
)[0]

mesh.export("hunyuan3d_4view.glb")
公式サンプルは front / left / back の3枚例です。

一方、公式 Gradio は right を正式な入力枠として持ち、内部辞書にも right を追加します。したがって4枚入力は現行UI実装で明確にサポートされています。

8. テクスチャ生成

Hunyuan3D-2mv の形状生成後、Hunyuan3D-Paint を使ってテクスチャを作れます。

公式の textured_shape_gen_multiview.py 例では、形状は複数ビューから生成し、テクスチャは front画像 を渡す例になっています。

from hy3dgen.texgen import Hunyuan3DPaintPipeline

paint_pipeline = Hunyuan3DPaintPipeline.from_pretrained("tencent/Hunyuan3D-2")
textured_mesh = paint_pipeline(mesh, image=images["front"])
textured_mesh.export("hunyuan3d_4view_textured.glb")

別の公式例 fast_texture_gen_multiview.py では、複数画像のリストを Paint Pipeline に渡す例もあります。つまり「形状のマルチビュー」と「テクスチャのマルチビュー」は分けて考えた方がよいです。

9. 出力形式

現行 Gradio の Export UI が列挙している形式:

GLB

既定値。メッシュとマテリアルをまとめやすく、Blender / ゲームエンジンへの受け渡しに使いやすい。

OBJ

広く対応。テクスチャは別ファイル構成になる場合がある。

PLY

メッシュ・頂点属性用途。

STL

主に形状中心。テクスチャ用途には向かない。

GUIには Simplify Mesh、Target Face Number もあり、ポリゴン削減後にエクスポートできます。

10. VRAM / GPU

公式資料内で VRAM 数値が食い違っています。
  • メイン README: Shape 6 GB、Shape + Texture 合計 16 GB。
  • docs/source/modelzoo.md: Shape 6 GB、Shape + Texture 合計 24.5 GB。

したがって「Textureまで16GBあれば必ず足りる」とは断定できません。モデル、解像度、オフロード、ライブラリ版、実行経路によってピークが変わると考えるべきです。

GPU例ShapeShape + Texture判断
NVIDIA A30 24GB公式6GB条件を大きく上回る16GB記載なら範囲内。24.5GB記載とは境界付近/下回る可能性--low_vram_mode 併用が安全。公式数値の不一致があるので「確実」とは言わない。
RTX 3070 8GB公式6GB条件上は可能公式16GB / 24.5GBのどちらにも不足まず Shape専用。Textureは強いオフロード等なしには前提外。

--low_vram_mode 時、現行コードでは Texture Pipeline に model CPU offload を有効化します。

11. API / Blender / ComfyUI

公式 API Server

公式リポジトリには api_server.py がありますが、確認できた現行コードは基本的に単一 image を処理する構造です。GitHub Issueにも「APIモードでmulti-viewをどう使うか」という未解決質問があります。

4ビューを確実に使うなら、現時点では Gradio または Python Pipeline を優先。

APIサーバへ4画像を送れると断定できる公式仕様は今回確認できませんでした。

Blender Add-on

公式 README は、API Server を起動した上で Blender Add-on を使えるとしています。ただし、上記の理由から 公式Add-onで4ビューを直接送れるか は別問題であり、今回確認した情報だけでは保証できません。

ComfyUI

公式 README はコミュニティ実装として ComfyUI-Hunyuan3DWrapper、ComfyUI-3D-Pack を紹介しています。これらは Tencent 本体の Gradio と同一実装ではないため、4ビュー入力ノードの仕様や必要VRAMは各拡張側の版を個別確認する必要があります。

13. 実用的な推奨手順

STEP 1 — 画像準備

Front / Back / Left / Right を同じ高さ・同じスケールで用意。背景は単純化。

STEP 2 — Turboで試す

まず Hunyuan3D-2mv Turbo + 5 Steps + Standard Decodeで形状の方向整合性を見る。

STEP 3 — Seed固定

良い方向性が出たら Randomize Seed をOFFにし、同じSeedで設定だけ比較。

STEP 4 — 解像度を上げる

必要なら Decode High / Octreeを上げる。VRAMと時間を監視。

STEP 5 — Mesh確認

裏面、左右、薄い部品、手足、穴、非対称部分を3Dビューで確認。

STEP 6 — Texture

形が確定してからPaint。形状生成とテクスチャ生成を同時に調整しない。

STEP 7 — Simplify

ゲーム用途なら Target Face Number を調整し、見た目と負荷のバランスを確認。

STEP 8 — GLB出力

Blenderに読み込み、法線・UV・マテリアル・スケール・原点を最終調整。

最初に試す設定

モデル: Hunyuan3D-2mv Turbo
画像: Front + Back + Left + Right
Remove Background: ON
Randomize Seed: ON（探索中）
Generation Mode: Turbo
Inference Steps: 5
Decoding Mode: Standard
Octree Resolution: 256
Guidance Scale: 5.0
Number of Chunks: 8000
出力: GLB

形状が複雑で崩れる場合に Fast / Standard、Steps増加、Decode High を比較します。一度に複数パラメータを変えると原因が分からなくなるため、1項目ずつ変えるのが安全です。
