1. まず押さえること

  • GPU は 1 枚だけで、大きな AI は同時に 1 つしか動かせません。Ollama の Qwen 27B だけで VRAM 24 GiB のうち 22 GiB を使います。入口ページ（8080）から起動すると、GPU を取り合うほかのサービスを先に止め、Ollama のモデルを降ろしてくれます。 Strata の 5 つどうしも、1 つを起動するとほかが自動で止まります。
  • 自動で起動するのは Ollama と入口ページだけです。それ以外（Strata・3D 生成・Open WebUI）は、使うときに入口ページから起動します。
  • Ollama と Strata の違い。Ollama は GPU に収まるモデルを手軽に動かします。Strata は Qwen3.8-Flash-Next という 40〜85 GiB の大きなモデル（MoE）を、GPU・RAM・CPU に分けて動かす専用のエンジンです。起動に 20〜80 秒ほどかかり、RAM を 25〜44 GiB 使います。
  • 文脈長（一度に扱えるトークン数）は、2026-10-18 に「A30 に全部載る最大」にそろえました。Ollama は KV キャッシュを 8 ビットにして モデルごとに上限を決め（27b 114,688・it-qat 65,536・e4b と IQ4_XS 131,072）、Strata は 5 つともモデルの上限 262,144 です。文脈長と KV キャッシュの大きさは第 5 節にまとめました。
  • どれも同じ API の形で呼べます。Strata はポート 8082〜8086 の /v1（OpenAI 互換）です。 Ollama は 127.0.0.1:11434 で、この機体の中からしか呼べません。チャット画面の Open WebUI は、この両方につながっています。
意見用途ごとの目安（根拠は下の各節の評価と実測）
  • ふだんの質問や画像を見せる質問: qwen3.8:27b。速く（34〜38 tok/s）、画像も読めて、追加 3 試験で 100%。
  • 難しい数学など長い推論: gemma4:31b-it-qat（10-08 の評価では ctx32k の名前で 3D 数学を全問正解・ローカル最短の 441 秒。 10-18 からは it-qat 本体が同じように全部 GPU に載る設定になった）か、Strata 公式 IQ3_XXS（全問正解、839 秒）。
  • コーディング: 点数は gemma4:31b-it-qat（92%）が最も高いものの、699 秒かかります。 速さとの釣り合いでは qwen3.8:27b（83%・243 秒）か Strata 公式 IQ3_XXS（84%・464 秒）。
  • 画像から 3D モデル: 正面・背面・左・右の 4 枚がそろうなら Hunyuan3D-2mv。材質まで欲しいなら Pixal3D。 穴のない閉じたメッシュが要るなら ComfyUI の防水メッシュのワークフロー。

3. Ollama のモデル（4 つ）

Ollama（版 0.40.5）は、モデルを読み込んで文章を生成するサーバーです。この機体では常に起動していて、 呼ばれたモデルを GPU に読み込みます（入りきらない分は CPU 側に置きます）。5 分使わないと VRAM から降ろします。サイズは ollama list の値です。

4. Strata のモデル（5 つ）

Strata（Niko1221/Strata、版 v0.1.44.1）は、MoE という形のモデルを CPU と GPU で分担して動かすエンジンです。 5 つのモデルはどれも Qwen3.8-Flash-Next 系で、各層に 512 の「専門家（エキスパート）」を持ち、1 トークンごとにそのうちの一部だけを使います。

  • 分担の仕組み: よく使われるエキスパートを GPU のキャッシュに置き、残りは RAM に置いて CPU で計算します。 だから VRAM 24 GiB の機体でも、40〜85 GiB のモデルが動きます。
  • 先読みで速くする（MTP の投機デコード）: 小さな予想役（draft 層。5 モデルで共有、6.5 GiB）が数トークン先を予想し、 本体がまとめて確かめます。当たった分だけ速くなります。
  • 同時に 1 つだけ: 1 つを起動すると、ほかの 4 つは自動で止まります（systemd の Conflicts=）。
  • 文脈長（コンテキスト長）: 5 つとも 262,144 トークン（モデルの上限。2026-10-18 に 131,072 から広げた）。 KV キャッシュは 8 ビット（int8）で、262,144 分で 3.35 GiB（engine のログ）。置き方はモデルで違う（第 5 節）。速さの設定は第 9 節。
  • 呼び方: http://<サーバー>:808x/v1（OpenAI 互換）。Open WebUI にも 5 つともつないであります。

5. 文脈長と KV キャッシュ（文章の AI 9 モデル）

文脈長（コンテキスト長）は、1 回の会話で扱えるトークン数の上限です。入力・会話の履歴・思考・答えをすべて合わせた長さで、 これを超える文章は読めません。KV キャッシュは、読んだトークンの途中の計算結果を残しておくメモリです。文脈長を長くするほど KV キャッシュも比例して大きくなり、VRAM を使います。2026-10-18 に、9 モデルとも「A30 に収まる最大」にそろえました。

  • KV を 8 ビットに縮めた。Ollama は f16（16 ビット）から q8_0（8 ビット）に変え、同じ VRAM で約 2 倍の長さを持てるようにした （Ollama 全体の設定）。Strata はもとから int8（8 ビット）。精度の低下はごく小さい（Ollama の説明）。
  • 決め方。Ollama はモデルを実際に読み込み、全部の層が GPU に載る最大を探した（載らないと Ollama は黙って層を CPU に移し、遅くなる）。 Strata は KV が小さいので、5 つともモデルの上限 262,144 にした。
  • 1 トークンあたりの大きさがモデルで違う理由。KV を持つのは「文章全体を見る注意の層」だけ。Qwen3.8 系は 4 層のうち 1 層だけがそれで、 残りは長さに関係なく一定の状態を持つ。Gemma 4 は多くの層が「直近 1,024〜1,536 トークンだけを見る窓付き」で、その分は一定の大きさで済む。

KV の型: Ollama の q8_0 と Strata の int8 の違い

どちらも「8 ビットの整数と、何個かごとに 1 つの倍率（f16）」で数値を持つ、同じ考え方の 8 ビット形式です。名前が違うのは、エンジンごとに 別の実装だからです。Strata には q8_0 が無く、Ollama には int8 が無いので、同じエンジンの中でどちらかを選ぶことはできません。

意見Strata は int8 のまま、Ollama は q8_0 のままがよい
  • Strata は int8 が最善です。Strata で選べる 4 つのうち、fp16 と同じ精度で大きさが半分になるのは int8 だけです。上流の既定で、公開されている品質の数値はすべて int8 で測られています。この機体でも fp16 にして点は変わりませんでした。q8_0 は倍率の単位が細かい（32 個）ぶん理屈では少し正確ですが、int8 でも fp16 との差が 測れないので、差は出ない見込みです（Strata では q8_0 を選べないので、確かめる方法もありません）。
  • Ollama は q8_0 が最善です。Ollama で 8 ビットの型はこれだけです。q4_0 にすればさらに半分になりますが、精度が落ちます。
  • Strata のさらに小さい型:
    • k8v4（K を 8 ビット、V を 4 ビット）は int8 より 23% 小さい（1 セル・1 層 816 バイト）。上流では RTX 3090・Coder・198K で 85 → 99 tok/s。 この機体で 2026-10-18 に測り、採らなかった（下の「k8v4 を測った結果」）。
    • q4_0 は int8 の約半分（576 バイト）。ただし長い文書でパープレキシティが 8〜12% 悪くなる（上流の実測）。この機体では測っていない。

k8v4 を測った結果（2026-10-18）

Strata の 5 モデルで、いまの int8 と k8v4（K を 8 ビット・V を 4 ビット）を比べました。測り方はこれまでと同じ速さの 3 条件（greedy・3 回の中央値）に、 約 19 万トークンの資料を読ませて答えを照合する試験と、公式版だけ128K トークンの文章の 10・50・90% の位置に隠した合言葉を探させる試験（needle）を足しました。

意見k8v4 は採らず、5 モデルとも int8 のままにした
  • 使った分だけ KV を取る 3 つ（公式・Swift・Coder）では効かない。短い会話では KV がもともと 0.25 GiB しか無く、k8v4 で減るのは 0.04 GiB だけ（枠は 28 増えるだけ）。 19 万トークンでも生成の速さは同じで、資料を読む速さは 8% 落ちた。
  • KV を全部 VRAM に置く公式 IQ3_S では少し効く（枠 +373、4K +3%、19 万トークンの生成 +5%）。ただし資料を読む速さは −5% で、差は測り直しの揺れ（1〜2%）より少し大きい程度。 V を 4 ビットにする精度の代わりに取るほどではない、と判断した。
  • KV を RAM に置く RVN では遅くなる（短い質問 −10%、19 万トークンの生成 −7%）。
  • 答えはどれも正しく、needle も 3/3 で、この試験の範囲では精度の差は見えなかった。精度を細かく比べる道具（上流の kv_precision_compare.py）はこの版に無く、測っていない。
⚠ 計測の途中で起きたこと
  • 公式 IQ3_S で 19 万トークンを読ませた直後に起動した RVN（int8）が、エキスパートを RAM に写している途中で systemd-oomd に止められた（14:24）。 モデルのファイルのキャッシュは捨ててあったが、RAM の本当の空きは 22 GiB しかなかった。10 分後に同じ設定で測り直すと、88 秒で起動した。原因は切り分けていない。 RVN は 5 モデルで最も RAM を使う（約 46 GiB を固定）ので、ほかのモデルの直後に起動するときは注意が要る。

⚠ 長い文脈を使うときの注意

9. Strata の速さの設定と文脈長 262,144（2026-10-18 に反映）

「A30 に収まるように、文脈長と KV キャッシュを最大に」という指示で、Strata の 5 モデルの文脈長をモデルの上限 262,144 にしました。 あわせて、Strata の新しい速さの設定をこの機体で測り、効いたものを正式な設定（tools/strata/stra/config.py）に入れました。

  • --adapt-async: GPU に置くエキスパートの入れ替えを、生成の合間に裏で進める。5 モデルとも 6〜14% 速くなったので全部に入れた。
  • 通常モード: エキスパートを全部 RAM に置く（約 42 GiB）。RAM に収まる 3 モデル（Coder・公式 IQ3_XXS・Swift）で常駐モードより 8〜20% 速い。 公式 IQ3_S と RVN はエキスパートが大きく収まらないので、常駐モードのまま。
  • --kv-grow（通常モード限定）: KV キャッシュは使った分だけ VRAM に取り、残りをエキスパートの枠に回す。これで文脈長を 2 倍にしても枠は減らず、速さも変わらない。
  • KV を RAM に置く（KV ストリーミング、常駐モード向け）: VRAM には直近の 65,536 トークン分だけ残す。RVN では枠が増えて 4% 速くなったので入れた。公式 IQ3_S では差が 2% で RAM が 2.3 GiB 増えるので入れなかった。

測り方は上の「生成の速さの比較」と違います（乱数を使わない greedy、思考ありは effort low・最大 512 トークン、3 回の中央値）。 このため値もそろいません。比べられるのは、同じ表の中の列どうしだけです。

10. 用語集

トークン
AI が文章を区切って扱う単位。単語や文字のかけら
tok/s
1 秒に作るトークンの数。大きいほど速い
prefill
答えを書き始める前に、入力の文章を読み込む処理。長い入力ほど時間がかかる
文脈長（コンテキスト長）
1 回の会話で扱えるトークン数の上限。入力・会話の履歴・思考・答えの合計。Ollama では num_ctx、Strata では --max-context
KV キャッシュ
読んだトークンの途中の計算結果（Key と Value）を残しておくメモリ。これがあるので、1 トークン作るたびに過去を全部計算し直さずに済む。 大きさはトークン数に比例し、文脈長を長くするほど VRAM を使う
f16 / q8_0 / int8
KV キャッシュの数値の持ち方。f16 は 16 ビット（Ollama の既定）。q8_0（Ollama）と int8（Strata）はどちらも 8 ビットの整数と ブロックごとの倍率で、大きさが f16 の約半分。違いは倍率をかける単位（q8_0 は 32 個、int8 は 64 個）で、精度はどちらも f16 とほぼ同じ。第 5 節の「KV の型」
k8v4 / q4_0（KV）
Strata で選べる、さらに小さい KV の型。k8v4 は K を 8 ビット・V を 4 ビット（int8 より 23% 小さい）、q4_0 は全部 4 ビット（約半分。長い文書で精度が落ちる）。 k8v4 は 2026-10-18 に測り、速さがほとんど変わらないので採らなかった（第 5 節）。q4_0 は測っていない
窓付きの注意（sliding window）
直近の一定数（Gemma 4 では 1,024〜1,536）のトークンだけを見る層。KV の大きさが文脈長に関係なく一定で済む
kv-grow / KV ストリーミング
Strata の KV の置き方。kv-grow は使った分だけ VRAM に取る（通常モード限定）。KV ストリーミングは KV を RAM に置き、VRAM には直近の一部だけを残す。 どちらも空いた VRAM をエキスパートのキャッシュに回して速くするため
思考（thinking）
答える前に、AI が内部で考える文章を書く機能。正確になるが、長いと答えまで時間がかかる
思考の上限（予算）
思考の長さの上限。達すると、思考を打ち切って答えを書かせる
MoE
Mixture of Experts。モデルの中に多数の専門家（エキスパート）があり、1 トークンごとに一部だけを使う形。全体は大きいが、1 回の計算は軽い
量子化
モデルの数値を少ないビット数に丸めて小さくすること。ビットが少ないほど小さく速いが、元のモデルから離れる。 目安は Q4_K_M・Q4_0・IQ4_XS が約 4〜5 ビット、IQ3_S が約 3.4、IQ3_XXS が約 3.1、IQ1_M が約 1.75 ビット
abliterated
モデルの中の「頼みを断る」働きを取り除く改変
fine-tune
できあがったモデルに追加の学習をして、性質を調整すること
MTP・投機デコード
小さな予想役が数トークン先を予想し、本体がまとめて確かめる方法。当たった分だけ速くなる。答えの傾向は変わらない（計算の丸めの違いだけ）
常駐モード / 通常モード
Strata の動かし方。常駐モードは RAM を節約し、通常モードは全部のエキスパートを RAM に固定して速くする（RAM を多く使う）
VRAM / RAM
VRAM は GPU の中のメモリ（24 GiB）。RAM はコンピューター本体のメモリ（64 GB）
ポート
サービスの窓口の番号。ブラウザでは http://<サーバー>:8080 のように指定する
unit（systemd）
サービスを起動・停止する仕組みの単位。この機体のサービスは「自動で起動しない」設定にしてある（Ollama と入口ページを除く）
OpenAI 互換 API
ChatGPT の API と同じ形で呼べる窓口。対応している道具からそのまま使える
