# open-webui

Open WebUI（ポート 8081）の運用上の事実。ポート配置と起動・停止は
`knowledge/10-silver/areas/web-services.md` を Read する。

## 置き場

- 設定は `~/.config/open-webui/open-webui.env`（systemd ユニットの `EnvironmentFile`）。
- データは `~/.local/share/open-webui/data/webui.db`（SQLite）。チャットは `chat` テーブルの
  JSON に、使ったモデル名を id そのままで持つ。
- 認証は有効（`WEBUI_AUTH=true`）。既定モデルは `DEFAULT_MODELS` で指定する。

## モデル名は約 28 文字で切れる

- **モデル選択の一覧は約 28 文字で打ち切られ、それ以降は `...` になる。** 違いが名前の末尾に
  しか無いと、一覧上で区別できない。2026-09-27 に `qwen3.8-flash-next:125b-a6b-IQ1_M` など
  5 つの量子化違いが、共通の `125b-a6b-` までしか表示されず区別できなくなった。
- 一覧に併記されるパラメータ数（例 `176.9B`）は量子化が違っても同じ値になるため、区別に使えない。
- **違いは名前の前寄りに置く。** 上記は `qwen3.8-flash-next:IQ1_M` のように量子化を `:` の直後に
  出し、全モデル共通で区別に役立たない `125b-a6b-` を外して解決した。

## 改名は安全で即時（ollama cp の性質）

- **`ollama cp` はマニフェストだけを複製する。重みは共有するのでディスクは増えず、一瞬で終わる。**
  実測で、110GB 級を含む 5 モデルを複製してもモデル置き場は 440GB のまま変わらなかった。
- したがって改名は `ollama cp <旧> <新>` → `ollama rm <旧>` で行える。元に戻すのも
  `ollama cp <新> <旧>` だけでよい。重みは消えないので安全。
- **ただし、改名すると過去のチャットが参照していたモデル名は解決できなくなる。** 会話の内容は
  残るが、そのチャットで続けるにはモデルを選び直す必要がある。改名前に
  `webui.db` の `chat` テーブルを見て、影響を受けるチャットの件数を確かめる。
