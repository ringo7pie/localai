使う前に、動いているか見る

  1. サービスが上がっているか
  2. API が応答するか

    PROCESSOR 列が 100% GPU なら正常。n%/m% CPU/GPU と出たら CPU に溢れていて、生成が数分の一に落ちる。UNTIL 列は常駐が切れるまでの残り時間。 何も表示されなければ、まだ誰も呼んでいないだけで異常ではない。

VRAM と文脈長

この構成でいちばん重要な制約。24576 MiB の器に 17 GB の重みを置いた残りが、 会話を覚えておくための KV キャッシュに使える分になる。文脈長はそこから決まる。

グラフの読み方 バーは 81920 以上でほぼ同じ長さになる。VRAM が余っているのではない。 Ollama が「これ以上は載らない」と判断して層を CPU 側へ移した結果、VRAM の消費が そこで頭打ちになっている。つまりバーの長さでは限界を判定できない。 判定に使うのは ollama ps の PROCESSOR 列だけ。
結論 65536 が、この機体で全層を GPU に載せられる上限。 81920 では既に 9% が CPU に落ちる。残り約 2375 MiB は画像処理と同時リクエストの余地として空けてある。
機能

思考・道具・画像

このモデルは 3 つとも使える。いずれもこの機体で応答を確認済み。

思考（thinking）— 既定で有効

答える前の推論が message.thinking に、結論が message.content に分かれて返る。 そのぶんトークンを消費して遅くなるので、単純な変換や分類では切る。

"think": true のときの実際の応答: thinking に「17 × 23 = 17 × 20 + 17 × 3 = 340 + 51 = 391」、 content に「17 × 23 = 391」。

道具（tools）— 関数呼び出し

関数の定義を渡すと、モデルは呼ぶべき関数と引数を message.tool_calls に入れて返す。 実際に関数を実行するのは呼び出し側の仕事で、結果を role:"tool" のメッセージとして戻すと会話が続く。

画像（vision）

画像は images 配列に base64 文字列そのものを入れる。 data:image/png;base64, の接頭辞は付けない。

設定

設定を変える

サーバ全体の既定値は systemd の drop-in で決める。1 回のリクエストだけ変えたいなら options を渡す。

サーバ全体（再起動が要る）

いま入っているのは次の 1 行だけ。

変数いまの値効果と注意
OLLAMA_CONTEXT_LENGTH65536 文脈長の既定。上げると CPU に溢れる。変更したら必ず ollama ps で 100% GPU を確認する
OLLAMA_KEEP_ALIVE未設定（5 分） 無操作で常駐を解く時間。-1 で常駐しっぱなしになるが、VRAM を 22 GB 占有し続ける
OLLAMA_HOST未設定（127.0.0.1） 0.0.0.0 にすると LAN に開く。認証機構は無いので、開く前に到達範囲を決めること
OLLAMA_IGPU_ENABLE未設定 1 で内蔵 GPU（Intel UHD 770）も候補に入る。A30 があるので入れる理由は無い

1 リクエストだけ変える

注意 num_ctx を既定と違う値で呼ぶと、Ollama はその長さでモデルを載せ直す。 17 GB の読み込みに約 60 秒かかるため、値を混ぜて使うと毎回待たされる。 基本は既定の 65536 のまま使い、変えるなら統一する。
保守

サービスとモデルの管理

systemctl と /etc 配下の編集には root 権限が要る。 モデルの操作（pull や rm）には要らない。

別のモデルを試すとき /usr/share/ollama/.ollama/models に置かれる。ディスクは 1.5 TB 空いているので容量の心配は要らないが、 24576 MiB に収まるかどうかが唯一の基準。目安として 4bit 量子化で 18 GB 前後までしか載らない。 入れたら ollama ps で 100% GPU を確認すること。

症状原因対処

正常		 17 GB の重みをディスクから VRAM へ読み込んでいる。約 60 秒かかる 待つ。2 回目以降は 23〜26 tok/s に戻る。応答 JSON の load_duration で読み込み時間が確認できる

正常		 OLLAMA_KEEP_ALIVE の既定が 5 分。無操作で VRAM から降ろされる 常用するなら drop-in に OLLAMA_KEEP_ALIVE=-1 を足す。残り時間は ollama ps の UNTIL 列

範囲

やっていないこと

意図的に手を付けていない。必要になったら個別に決める。

  • LAN への公開。待ち受けは 127.0.0.1 のみ。Ollama に認証機構は無いので、開くなら到達範囲を先に決める必要がある
  • 常駐の延長。OLLAMA_KEEP_ALIVE は既定の 5 分のまま。延ばすと 22 GB を占有し続けるため、GPU を他に使うかどうかで決まる
  • vLLM / llama.cpp。同時リクエストのスループットが要るなら vLLM に利がある。A30 は compute 8.0 で FP8 の演算器が無いため、量子化は AWQ か GPTQ になる
  • Claude Code をこのモデルで動かす。Ollama は ollama launch claude --model qwen3.8 という起動方法を案内しているが、未検証。この機体では試していない
